# 개발 명세

## 정보 구조와 랜딩페이지의 차이
홈은 정보 탐색의 입구입니다. 프로그램·학교·돌봄·브랜드·비용을 독립 문서로 분리하고 각 페이지에서 상담으로 연결합니다. 긴 단일 문서의 앵커 이동을 기본 탐색으로 사용하지 않습니다.

| 메뉴 | 현재 문서 | 권장 정식 경로 | 주요 내용 |
|---|---|---|---|
| 홈 | index.html | / | 히어로·핵심 사실·메뉴 안내·학교·모브랜드 |
| 프로그램 | program.html | /program | 비교표·준비/학교생활/귀국 여정·고민 진단 |
| 학교 | school.html | /school | IGS·1863·최대 10주·사진·참가 조건 자료 대기 |
| 현지 케어 | care.html | /care | 상주 코칭·리포트·동행·생활/응급 범위 |
| 브랜드 소개 | about.html | /about | 톡픽·대표 자료·1기 기록·현지 파트너 |
| 비용·FAQ | guide.html | /guide | 예정 총액·예약금·별도 비용·FAQ 8개 |
| 상담 | contact.html | /contact | 연락처·상담 입력·필수/선택 동의 |

## 와이어프레임
공통: 검토 표시 → 로고/모브랜드 + 주 메뉴 + 상담 → 본문 → 모브랜드/운영 주체/연락처 푸터.
홈 데스크톱: 왼쪽 헤드라인/프로그램·상담 버튼 + 오른쪽 실제 참고 사진 → 사실 4열 → 탐색 링크 3열 → 학교 사진/설명 2열 → 모브랜드 → 상담.
상세: 페이지 제목/요약 → 해당 주제 콘텐츠 → 상담. 운영진·기록·파트너는 소개 페이지 내부 순서 유지.
모바일: 메뉴 토글 → 사진/텍스트 1열 → 사실 2열 → 탐색 1열. 비교표만 가로 스크롤 허용.

## 컴포넌트
- SiteHeader: 홈 링크·모브랜드·5개 정보 메뉴·상담. 현재 문서 aria-current=page.
- MobileMenu: button/aria-expanded/aria-controls. 토글, Escape로 닫기 및 토글 포커스 복귀. 모달 아님, 포커스 가두지 않음.
- HomeHero: 2열, 모바일 순차 스택. 사진 출처 성격이 이미지 위에 표시됨.
- ExploreLinks: 진짜 문서 링크 3개, 전체 영역 클릭 가능.
- PageTitle: 페이지당 h1 하나. 출처 없는 평가/랭킹 금지.
- ComparisonTable: 의미론적 table, 좁은 화면에서 이 컴포넌트만 스크롤.
- Journey: 8단계, 학교 10주와 전후 준비/관리 기간 구분.
- ConcernDiagnosis: 프로그램 페이지에서 4개 고민 단일 선택. 선택 상태 aria-pressed, 결과 aria-live=polite. 클릭 시 답변·맞춤 상담 링크 표시. 링크 contact.html?concern=0..3. 상담 페이지는 유효 범위 숫자만 받아 해당 고민을 필드에 표시. 자유 텍스트 쿼리를 HTML로 삽입하지 않음.
- SchoolGallery: 로컬 이미지·alt·출처·사진 성격. 실제 프로그램 기록과 혼동 금지.
- CareBlocks: 확정 코칭·주간 리포트와 미확정 운영 항목 구분.
- PartnerCard: about 페이지 하단 한 곳, 로고 폭 160px. 협업 파트너·호주 현지 정착/생활 지원 역할. 다른 페이지의 사진 설명에는 파트너명을 반복하지 않음.
- FAQ: 네이티브 details/summary, 8개. 여러 개 동시에 열 수 있음.
- ConsultationForm: 미연결 상태 명시, submit 방지. 필수 개인정보·법정대리인 동의, 선택 마케팅 동의 분리. 예약 버튼 비활성. 정책이 없는데 유효한 동의를 받았다고 처리하지 않음.

## 실제 접수 연동 작업
현재는 서버·DB·쿠키·브라우저 저장소 사용 없음. 문의 접수를 추가할 때 필수 항목/정책 전문/보유 기간/거부 영향/법정대리인 확인/마케팅 채널을 먼저 확정합니다. 프론트와 서버에서 검증하고, 접수 완료 응답 후에만 성공 화면을 표시합니다. 중복 클릭·오류·재시도·접수 식별자 정책을 정합니다. 전화·메일 클릭과 접수 완료는 구분합니다.
